# Open Issues — The Loophole Ledger

> A system that cannot say "I don't know" will fabricate. Every BLOCKED item in
> Section 21.1 is a place this system must explicitly return "unavailable"
> rather than a plausible number. These must be tracked in `OPEN_ISSUES.md` and
> surfaced in every thesis's `warnings`.
>
> — AGENTS.md Section 21.4

This file is the authoritative register of (a) inputs the system **cannot**
source, (b) limitations that are inherent rather than fixable, and (c) defects
and gaps deferred to a later phase. Nothing here is ever silently worked
around.

**Status legend**

| Status | Meaning |
|---|---|
| `BLOCKED` | No source exists. The consuming function raises `NotImplementedError`. |
| `LIMITATION` | Inherent. Cannot be fixed by more work — must be disclosed in output. |
| `DEFERRED` | Scheduled for a named later phase. |
| `MITIGATED` | A defect that has been fixed. Retained for the audit trail. |

## Part 1 — Blocked inputs (Section 21.1)

These are registered in `config/series_registry.yaml` under `blocked:`, so an
attempt to use one fails loudly and with a reason rather than quietly
substituting a proxy.

### O-1 — `risky_credit_growth_pct` — BLOCKED

No clean free series exists for leveraged-loan growth.

**Explicitly forbidden substitute:** total credit growth is **not** an
acceptable proxy (Section 21.1 states this directly). The two measure different
things and diverge precisely when the signal matters.

**Affects:** the credit-cycle component of the regime classifier (Module 3).
The classifier must degrade to its remaining measures and disclose the absence.

### O-2 — `iron_ore_change_pct` — BLOCKED

No clean free source for iron ore prices.

**Affects:** the industrial-metals divergence check (Section 20.10). The
function must return "unavailable" for the iron-ore leg rather than
substituting copper or a broader metals index.

### O-3 — `ppp_implied_rate` — BLOCKED

OECD publishes PPP conversion factors but exposes no clean free API.

**Path:** MANUAL entry only. Section 21.4 notes any MANUAL input must appear as
"Manual Entry" in output, so it can never be mistaken for a live observation.

**Affects:** the PPP leg of FX modelling (Module 12). UIP and carry remain
computable from live data; only the PPP-anchored view is unavailable.

### O-4 — `supercore_direction` — BLOCKED
Per audit finding O-8 there is **no valid BLS construction for supercore**.
"All items less shelter" was previously and incorrectly labelled supercore; the
containing category ("all items") includes food and energy, so the construction
excludes only shelter and is not the intended measure.

**Affects:** the inflation classifier must degrade to **5 of its 6 measures**
rather than 6 of 7. This is the canonical example of Section 21.0 rule 4 — the
substitution must never recur.

**Re-confirmed 2026-09-17 (D-047).** The other two dispersion measures that were
blocked alongside this one — `median_cpi_direction` and `trimmed_mean_direction`
— turned out to be **live** (see O-26). `supercore_direction` was checked in the
same probe and **genuinely is not available**, so its block stands on evidence
rather than on inheritance. That distinction matters: the block survived an
audit that killed two of its neighbours, which is the strongest form of
confirmation this ledger records.

**It is the one absence that matters most**, because supercore is the measure the
Fed most often cites in its own communication — so the classifier's coverage of
the core-inflation spectrum is incomplete precisely where a reader would look
for it.

### O-39 — `inflation_surprise_bp` — BLOCKED (no free consensus forecast)

A **genuine** inflation surprise is `actual − expected`, and the expected leg is a
consensus forecast. **O-8** already records that no free source for consensus
exists, so this input cannot be supplied as defined.

**Registered `blocked:` in `config/series_registry.yaml` (D-052)**, with the probe
evidence written verbatim rather than summarised — four queries, four different
failure modes:

| query | result |
|---|---|
| `"CPI forecast"` | `EmptyDataError` |
| `"CPI consensus"` | `EmptyDataError` |
| `"consumer price index forecast"` | "No results found" |
| `"inflation expectation"` | returns only `T5YIFR` / `EXPINF*YR` |

**The fourth row is the one that matters**, because those series *look* like a
surprise and are not: `T5YIFR` and `EXPINF1YR`/`EXPINF2YR`/`EXPINF3YR` are
**market- and model-implied expectations**, not a survey consensus of the printed
CPI. Substituting one would produce a number that is plausible, wrong, and
unfalsifiable by any downstream check — §21.0's exact prohibition. **A block is a
claim about the world and it decays** (O-21, three occurrences): this entry should
be re-probed with `fred_search` in the same way `median_cpi_direction` and
`trimmed_mean_direction` were, since two of the three "blocks" in that batch were
false.

**Affects:** `cross_asset_transmission` (Module 5.6). The function keeps the input
in its contract and in `inputs_used`, and emits a warning naming it as
**reported but not used** — the disclosed form of a *declared, consumed,
unreachable* input. The undisclosed form is forbidden: mutation `M1.1` folds the
surprise into the nominal leg, and no test may pass while it does.

## Part 2 — Inherent limitations (Section 21.4)

Cannot be resolved by additional implementation. Must be disclosed.

### O-5 — Unobservable natural rates: `r*`, `u*`, potential GDP, TFP — LIMITATION

These are unobservable by nature. The system carries **config estimates only**:

| Input | Config default | Note |
|---|---|---|
| `r*` | 0.5 | Track NY Fed Holston-Laubach-Williams; Phase 5+ Kalman. The single largest driver of policy-rule dispersion. |
| `u*` (NAIRU) | 4.4 | CBO estimate. Must track CBO revisions. |
| potential GDP | FRED `GDPPOT` | CBO series, used directly per D-002. |
| TFP | not used | Cobb-Douglas skipped in favour of `GDPPOT` (D-002). |

**Required disclosure:** their uncertainty must propagate into every downstream
confidence value via `compute_confidence(depends_on_unobservable=True)`. A
policy gap computed from an unobservable `r*` is not a measurement, and the
thesis must not present it as one.

---

### O-6 — Pre-launch data vintages are unrecoverable — LIMITATION

Revision analysis (`prior_month_revision`, `two_months_ago_revision`) works
**only forward**. Vintage storage begins from the first snapshot this system
persists and cannot be backfilled.

**Consequence:** before enough history accumulates, revision reads must return
`None` — **never zero**. A zero would be indistinguishable from "no revision
occurred", which is a materially different claim.

**Mitigation in place:** `data_layer/persistence.py` writes timestamped
parquet snapshots keyed by retrieval time, which is what makes this history
exist at all. See `docs/BUILD_STATE.md`.

### O-7 — `gdp_potential` mixes measurement with projection — MITIGATED

Discovered by live execution (see `DECISIONS.md` D-002). FRED `GDPPOT` carries
CBO forward projections extending ~10 years beyond the current quarter — a live
snapshot retrieved 62 observations, **41 of them future-dated**.

**Resolved 2026-09-16.** Every consumer of `gdp_potential` filters to
`observation_date <= as_of` through `models.as_of.observation_as_of()`, so no
projection can be treated as realised capacity. A naive "take the latest value"
read would compute the output gap against the Q4 2036 projection.

**Where the filter lives:** `models/as_of.py`, not inside any one model. The
obligation was general — "every consumer of `gdp_potential`" — so the fix is
general too: a consumer gets the discipline by using the shared helper rather
than by remembering to write a comparison. `AsOfSeries` returns the withheld
count and horizon alongside the filtered points, so a model can disclose the
truncation instead of silently discarding it.

**Two further consequences found while implementing it** (both recorded as
decisions rather than absorbed):

* **D-009** — filtering alone was not sufficient. `GDPPOT` runs one quarter
  *ahead* of `GDPC1`, so the filtered series still had no same-quarter partner
  for its latest point. The gap must pair the latest **common** quarter; taking
  each series' own latest produced +0.29% where the correct answer is +0.83%.
* **D-010** — the registry had recorded the Q4 2036 projection as
  `verified_value`, i.e. the *evidence* for the verification claim. Corrected to
  the latest realised observation, with `verified_observation_date` and
  `verified_curve` now required for a `forward_looking` verified series.

**Verification:** `test_output_gap_from_snapshot_ignores_forward_projections`,
`test_output_gap_pairs_the_same_quarter_never_each_series_own_latest`,
`test_live_output_gap_is_computed_from_same_quarter_realised_data`, plus the
D-010 registry validators. Mutation-testing the filter's removal fails 4 tests.

**Residual limitation:** `gdp_potential` remains NSA while `gdp_real` is SAAR.
That is reported in the registry's `seasonality` field and assessed as
second-order (the gap shows no systematic quarterly pattern: Q1 +0.96,
Q2 +0.95, Q3 +1.21, Q4 +1.37 over 20 quarters). It is a documented limitation,
not a correction to apply — a seasonally unadjusted *potential* series has no
seasonal component to remove.

### O-8 — Consensus estimates unavailable — LIMITATION

No free source for consensus/analyst expectations. Economic **surprise**
calculation (actual minus expected) therefore cannot be computed.

**Consequence:** the system can report that CPI printed 3.71% YoY, but cannot
report whether that was above or below expectations. Much of the market reaction
function depends on the surprise, not the level. Any thesis relying on a
surprise component must disclose that it is absent.

## Part 5 — Known test-suite limitations

### The `live` marker is excluded from the default run

Live tests make real network calls and take **~7 minutes** for the full set. A
network dependency in the default suite is how a suite becomes something people
learn to ignore. They run explicitly (`uv run pytest -m live`) and in the
scheduled `live-data` CI job.

**Risk this accepts:** a wiring regression that only live execution can detect
(the `fred_series` index-shape discovery, D-004, D-005 and D-006 were all of
this class) will not be caught by the default `pytest` run. This is a
deliberate trade and the reason the `live-data` job exists on a schedule.
